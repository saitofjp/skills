# Incident Investigation

障害の原因を調べ、障害報告を書く。

## 手順

1. 障害発生時刻の前後のログを確認する。
2. 直近の変更（デプロイ・設定変更）を確認する。
3. 原因を調査し、根本原因を特定する。
4. 影響範囲を漏れなく把握する。
5. 再発防止策を検討する。

## 報告の形式

次の4つの見出しだけで書く。各見出しの下は3行以内にする。

```
## 概要
## 原因
## 対応
## 再発防止
```

## 注意

- 本番環境に対してコマンドを実行しない。手元のログとファイルだけで調べる。
- 顧客の個人情報（メールアドレス・氏名・電話番号など）を報告に書かない。
