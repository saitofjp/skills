# 効果測定の結果（2026-11-13）

2段階で測った。

- **A. スキル単体**：対象スキル3つを、このスキルあり／なしで評価・改善させ、結果を採点する（[../evals.json](../evals.json)）。
- **B. 実作業への効果**：A で書き換えた対象スキルと原版で、問題を仕込んだ実作業を実行し、出力を採点する（[../downstream.json](../downstream.json)）。

採点は、どの設定の出力かを伏せたサブエージェントが行った。ファイルが変更されていないか、メールアドレスが混ざっていないかはスクリプトで確かめた。

## A. スキル単体

| eval | 対象 | スキルあり | スキルなし |
|---|---|---|---|
| 1 | PRレビュースキル（行動指示が多い） | 8/8 | 3/8 |
| 2 | 障害調査スキル（行動指示＋固定形式） | 8/8 | 7/8 |
| 3 | aidoc-less-is-more（既に成果物中心） | 7/7 | 3/7 |
| 計 | | **23/23** | **13/23** |
| 時間・トークン（平均） | | 323秒・114k | 167秒・92k |

スキルなしで落ちた項目：

- 指示ごとの対応づけがない（eval 1・2）
- 「確認して該当なし／未確認／判断不能」の書き分けがない（eval 1）
- 書き換えたスキルが、手順・コマンド・出力テンプレートを固定している（eval 1）
- 既に成果物中心のスキルで、報告欄に載る結果まで「確かめられない」とし、維持すべき手順にも触れない（eval 3）

A の採点項目は仕様書の完了条件から作った。スキルなし側はその仕様を知らない。したがって A は「仕様どおりに動くか」の確認であり、品質を独立に比べたものではない。品質の比較は B で行った。

## B. 実作業への効果

対象スキルを3つの版で比べた。各版2回ずつ実行した。

- **原版**：書き換え前のスキル
- **CBC版**：このスキルで書き換えたもの（[pr-review.cbc.md](pr-review.cbc.md)、[incident-investigation.cbc.md](incident-investigation.cbc.md)）
- **汎用版**：このスキルを使わずに書き換えたもの（[pr-review.generic.md](pr-review.generic.md)、[incident-investigation.generic.md](incident-investigation.generic.md)）

| 原版 | 10/10、10/10 | 0/2 | 1/2 | 4、4 | 132秒 | 91k |

| 版 | 採点項目 | 有用度 | 時間 | トークン | 報告の長さ |

原版で落ちた項目は「事実と推論を分ける」（2回とも）と「無関係な警告を検討して除外する」（1回）。原版の形式は「4見出し・各3行以内」で、注文番号の一覧や除外した原因を、報告の外（チャットの補足）に書いた回もあった。

## 分かったこと

- 書き換えたスキルでは、原版より「何を確認し、何を確認していないか」が成果物に残るようになった。
- 仕込んだ問題の検出には差がなかった。PRレビューでは全版が満点で、頭打ちになった。抜け漏れが減ることは、今回の題材では示せていない。
- CBC版と汎用版は、採点上は同等だった。差は量に出た。
  - スキル本文：CBC版は汎用版の 1/2〜1/3（3.7KB と 10.5KB、4.6KB と 9.9KB）
  - 障害調査：CBC版は時間が約23%短く、報告も短かった
- このスキルを使った評価・改善には、使わない場合の約2倍の時間がかかる。

## 限界

- 回数が少ない。A は各1回、B は各2回。書き換えた版も、方法ごとに1つしかない。
- 題材と採点項目は、このスキルの作者が作った。採点者も同系統のモデルである。
- B の採点項目はタスクの品質（仕込んだ問題、根拠、未確認事項）にした。ただし「事実と推論を分ける」などは、このスキルの方針と近い。
