# 市立図書館 貸出システム サービス分割 設計書 v0.4

## 1. 目的

今の貸出システムは、一つのアプリケーションと一つのデータベースでできている（以下、旧システム）。これを貸出、会員、検索、通知の四つのサービスに分け、それぞれを別のチームが開発し、リリースできるようにする。

## 2. 引き継ぐ業務

- 会員は、窓口の端末か Web で本を借りる。返却は窓口だけで受け付け、どの館の窓口でも返せる。
- 会員は、連絡先としてメールアドレスか電話番号のどちらかを登録する。
- 一人が同時に借りられるのは10冊まで。団体会員（学校や施設）は30冊まで。
- 返却期限は貸出日から14日。1回だけ延長でき、延長するとその日から14日になる。
- 返却期限を過ぎた会員には、翌朝に知らせる。
- 検索画面では、本ごとに「貸出可」か「貸出中」かを表示する。

## 3. 構成

| サービス | 担当 | データ |
|---|---|---|
| 貸出サービス | 貸出、返却、延長 | loans DB |
| 会員サービス | 会員の登録と退会、借りられるかの判定 | members DB |
| 検索サービス | 本の検索 | 検索インデックス |
| 通知サービス | メールを送る | なし |

- サービスどうしの同期の呼び出しは HTTP、非同期のやりとりはメッセージキューを使う。
- 窓口端末アプリと Web アプリは、各サービスの API を直接呼ぶ。

## 4. データ

### 4.1 loans（貸出サービス）

| 列 | 説明 |
|---|---|
| id | uuid |
| member_id | 会員の uuid |
| copy_id | 蔵書（1冊ごと）の ID |
| loaned_at | 貸出日時 |
| due_date | 返却期限 |
| extended | 延長したか |
| status | `on_loan` / `returned` |

### 4.2 members（会員サービス）

| 列 | 説明 |
|---|---|
| id | uuid（新しく振る） |
| card_number | 会員証の番号（旧システムでの会員の ID） |
| type | `individual` / `group` |
| email | メールアドレス（必須。通知をメールで送るため） |
| status | `active` / `withdrawn` |

### 4.3 検索インデックス

- 本ごとに、書誌の情報と「貸出可／貸出中」を持つ。
- 毎晩2時に、検索サービスが loans DB を読んで作り直す。

## 5. 処理

### 5.1 貸出

1. 端末が POST /loans を呼ぶ（会員の ID と蔵書の ID を渡す）。
2. 貸出サービスは、会員サービスの GET /members/{id}/eligibility を同期で呼び、借りられるかを聞く。
3. 会員サービスは、上限を判定するために、貸出サービスの GET /members/{id}/loans/count を同期で呼ぶ。
4. 借りられれば loans に `on_loan` で INSERT し、キューに `loan.created` を送る。

- 端末は、5秒以内に応答が無ければ、同じリクエストをもう一度送る。

### 5.2 返却と延長

- 返却: 窓口端末が POST /loans/{id}/return を呼び、status を `returned` にする。
- 延長: Web から POST /loans/{id}/extend を呼ぶ。extended が false なら、due_date をその日から14日後にし、extended を true にする。

### 5.3 退会

- 会員サービスは、退会の処理の中で members.status を `withdrawn` にし、loans DB に直接つないで、その会員の `on_loan` の貸出を `returned` にする。本は後で窓口が回収する。

### 5.4 通知

- 通知サービスは `loan.created` を受け取り、会員に貸出の確認メールを送る。
- キューは、同じメッセージを2回以上届けることがある（at least once）。

## 6. API

| メソッド | パス | サービス | 呼ぶもの | 内容 |
|---|---|---|---|---|
| POST | /loans | 貸出 | 窓口端末、Web | 貸し出す |
| POST | /loans/{id}/return | 貸出 | 窓口端末 | 返却する |
| POST | /loans/{id}/extend | 貸出 | Web | 延長する |
| GET | /members/{id}/loans/count | 貸出 | 会員サービス | 貸出中の冊数を返す |
| GET | /members/{id}/eligibility | 会員 | 貸出サービス | 借りられるかを返す |
| POST | /members | 会員 | 窓口端末 | 会員を登録する |
| DELETE | /members/{id} | 会員 | 窓口端末 | 退会する |
| GET | /search | 検索 | 窓口端末、Web | 本を検索する |

- パスの会員 ID には、新しく振った uuid を使う。
- 失敗したときは 400 か 500 を返す。

## 7. 移行

1. 新しいサービスとデータベースを用意する。
2. 旧システムのデータベースから、会員と貸出中の貸出を新しいデータベースにコピーする。土曜の夜に行い、数時間かかる見込みである。その間も旧システムは動かしておく。
3. 窓口端末アプリを新しい版に更新する。端末は30館に約200台あり、1週間かけて館ごとに更新する。Web アプリは、最初の館を更新する日に新しい版に切り替える。
4. すべての端末を更新したら、旧システムを止める。

- 旧システムと新しいサービスに、同時に書き込むことはない。
- 手順3で端末に問題が起きたら、その端末を旧の版に戻す。
