# 経費精算システム 仕様書 v1.2

## 1. 概要と範囲

社員が立て替えた経費を Web から申請し、上長と経理の承認を経て、月に2回、本人の口座に振り込む。紙の申請書と押印の回覧を置き換える。

この版では次を扱わない。いずれも経理部の今の手順で続ける。

- 外貨での立て替え、仮払い（前払い）、法人カードの明細の取り込み
- 振り込んだ後の訂正と返金
- 退職した社員の、取り下げになった申請の精算（§3.2）
- スマートフォン向けのアプリ（Web 画面はスマートフォンのブラウザでも使える）

切り替えの日より前に紙で出した申請は、紙のまま最後まで処理する。申請画面には、紙で出した経費を本システムで出し直さないよう注意を出す。紙の申請との重複は検査しない。

## 2. 用語

- **申請者**: 経費を立て替えた社員。
- **上長**: 申請者の所属部署の部長。人事システムの組織情報から決まる（§4.2）。
- **代理承認者**: 上長が期間を決めて指名した社員。期間中は、その上長が承認者として記録された申請について、上長と同じ承認ができる。
- **経理担当**: 経理部の社員。
- **システム管理者**: 情報システム部の社員。申請の中身は見られない（§4.1）。
- **申請**: 1件以上の明細をまとめたもの。振り込みはこの単位で行う。
- **明細**: 1回の支払い。日付、金額、支払先、科目、領収書からなる。
- **締め時刻**: 毎月10日と25日の 17:00（日本時間）。休日でも動かさない。この時刻までに振込待ちになった申請が、その回に振り込まれる（§7.1）。
- **振込日**: 締め時刻の日から数えて5営業日後。営業日は銀行の営業日とする。

## 3. 申請の状態

### 3.1 状態

| 状態 | 意味 |
|---|---|
| 下書き | 申請者が作成中。本人にしか見えない |
| 上長承認待ち | 提出され、上長（または代理承認者）の承認を待っている |
| 経理確認待ち | 上長が承認し、経理担当の確認を待っている |
| 差し戻し | 上長か経理担当が理由を付けて申請者に戻した |
| 振込待ち | 経理担当が承認し、振り込みを待っている |
| 振込保留 | 振り込みに失敗し、経理担当の確認を待っている |
| 振込済み | 振り込みが完了した（終わり） |
| 取り下げ | 申請者が取り下げたか、§3.2 によりシステムが取り下げにした（終わり） |
| 却下 | 経理担当が、この申請では振り込まないと決めた（終わり）。経費として認めないときと、口座の問題で振り込めないとき（§7.2）があり、どちらかを理由に書く |

### 3.2 遷移

| 今の状態 | 操作 | 操作する人 | 次の状態 |
|---|---|---|---|
| 下書き | 編集（明細の追加、変更、削除） | 申請者 | 下書き |
| 下書き | 削除 | 申請者 | （申請ごと消える） |
| 下書き | 提出（§5 の検証を通ったとき） | 申請者 | 上長承認待ち |
| 上長承認待ち | 承認 | 上長、代理承認者 | 経理確認待ち |
| 上長承認待ち | 差し戻す（理由は必須） | 上長、代理承認者 | 差し戻し |
| 上長承認待ち | 取り下げる | 申請者 | 取り下げ |
| 経理確認待ち | 承認 | 経理担当 | 振込待ち |
| 経理確認待ち | 差し戻す（理由は必須） | 経理担当 | 差し戻し |
| 経理確認待ち | 却下する（理由は必須） | 経理担当 | 却下 |
| 経理確認待ち | 取り下げる | 申請者 | 取り下げ |
| 差し戻し | 編集（明細の追加、変更、削除） | 申請者 | 差し戻し |
| 差し戻し | 再提出（§5 の検証を通ったとき） | 申請者 | 上長承認待ち |
| 差し戻し | 取り下げる | 申請者 | 取り下げ |
| 差し戻し | 差し戻しから30日が過ぎる、または申請者が退職する | システム | 取り下げ |
| 振込待ち | 振込結果「成功」（会計システムから受け取るか、§7.2 により経理担当が入力する） | システム、経理担当 | 振込済み |
| 振込待ち | 振込結果「失敗」（同上） | システム、経理担当 | 振込保留 |
| 振込保留 | 振り込みに戻す | 経理担当 | 振込待ち |
| 振込保留 | 却下する（理由は必須） | 経理担当 | 却下 |

- この表に無い組み合わせはすべて受け付けない。画面にはその操作を出さず、API は 409 を返す。たとえば、振込待ちの申請は誰も取り下げも編集もできない。
- 再提出は、上長と経理のどちらが差し戻したかによらず、上長承認待ちに戻る。差し戻しの間に金額が変わりうるため、上長が見直す。
- 上長承認待ちのまま5営業日が過ぎると、毎朝 8:00 に上長と代理承認者へ催促のメールを送る。
- 差し戻しから23日が過ぎると、あと7日で取り下げになることを申請者に知らせる。退職による取り下げは退職日に行い、退職の後に差し戻されたときは、差し戻した時点で取り下げにする。

## 4. 権限

### 4.1 ロールと操作

| 操作 | 申請者（本人） | 上長・代理承認者（承認者になっている申請） | 経理担当 | システム管理者 | ほかの社員 |
|---|---|---|---|---|---|
| 下書きの作成、編集、削除と、差し戻しの申請の編集 | 可 | 不可 | 不可 | 不可 | 不可 |
| 提出、再提出、取り下げ | 可 | 不可 | 不可 | 不可 | 不可 |
| 申請と領収書を見る | 可 | 可（下書きは見えない） | 可（下書きは見えない） | 不可 | 不可 |
| 上長としての承認、差し戻し | 不可 | 可 | 不可 | 不可 | 不可 |
| 経理としての承認、差し戻し、却下 | 不可 | 不可 | 可（自分の申請は不可） | 不可 | 不可 |
| 振込保留から振り込みに戻す | 不可 | 不可 | 可（自分の申請は不可） | 不可 | 不可 |
| 振込ファイルの渡し直しと、振込結果の入力（§7） | 不可 | 不可 | 可（振込結果の入力は、自分の申請は不可） | 不可 | 不可 |
| 代理承認者の指名と解除 | 不可 | 上長のみ可 | 不可 | 不可 | 不可 |
| 組織情報の取り込みの状況を見る | 不可 | 不可 | 不可 | 可 | 不可 |

- ある社員が複数のロールにあたるときは、申請ごとに当てはまる列で判断する。ただし、一つの申請で上長（代理承認者を含む）として承認した人は、その申請の経理としての操作はできない。ほかの経理担当が行う。経理部には常に3人以上の経理担当がいる前提とし、これらの規則で操作できる人がいなくなることは無い。
- 「承認者になっている申請」には、付け替え（§4.2）の前の上長や、期間の終わった代理承認者が承認か差し戻しをした申請も含む。ただし見ることしかできない。
- 代理承認者の指名の解除は、すぐに効く。解除の後に届いた代理承認者の操作は 403 を返す。

### 4.2 承認者の決め方

- 上長は、提出（再提出を含む）の時点の組織情報で決め、申請に記録する。兼務している社員は、人事システムで主務とされる部署で決める。申請者が退職した後は、退職の前日の組織情報で決める。
- 上長が申請者本人になるとき（部長が自分の申請を出したとき）や、部長が空席のときは、組織上の一つ上の上長が承認する。組織の最上位で上長がいない社員（社長）の申請は、経理部長が上長として承認する。
- 代理承認者は、自分が申請者である申請を承認できない。その申請は上長だけが承認する。
- 上長承認待ちの間に、異動や退職で、記録した上長がその申請の上長でなくなったとき（申請者の異動を含む）は、毎日 6:00 の組織情報の取り込みで、上の規則で決め直した上長に付け替え、新しい上長にメールで知らせる。

## 5. 申請と明細のルール

提出と再提出のときに次を検証し、一つでも満たさなければ、理由を示して提出させない。

- 申請には明細が1件以上ある。
- 明細の金額は1円以上100万円以下の整数。申請の合計には上限を設けない。
- 明細ごとに領収書のファイルが1〜3個ある。ファイルは JPEG、PNG、PDF のいずれかで、1個 10MB まで。ただし科目が「旅費交通費」で、支払先が電車かバスのときは、領収書の代わりに乗った区間を入力すればよい。
- 明細の日付は、その申請を最初に提出した日か、それより前の60日以内。差し戻された後の再提出でも、最初の提出日で数える。
- 同じ日付、金額、支払先の明細が、自分のほかの申請（下書き、取り下げ、却下を除く）にあれば、提出できない（その申請を示す）。同じ日に同じ支払先へ同じ金額を正当に2回払ったときは、後の明細に理由を書けば提出できる（経理担当の画面には理由と一緒に出す）。

提出と再提出は、申請者ごとに一つずつ順に検証して状態を変える。同じ明細を入れた二つの申請を同時に提出しても、後のほうは重複として止まる。

却下か取り下げになった申請は、画面の「出し直す」で、明細を写した新しい下書きを作れる。写した明細の60日は、元の申請の最初の提出日で数える。経理担当の画面には、元の申請の却下や取り下げとその理由を並べて出す。

## 6. 領収書のファイル

- アップロードされたファイルは、ウイルス検査を通るまで、申請者本人にも「検査中」としか見せず、その間は提出できない。ウイルスが見つかったら、そのファイルを消し、画面とメールで申請者に知らせる。検査が30分を過ぎても終わらないときは、システム管理者にメールで知らせる。
- ファイルは本システムのストレージに置く。見るときは、§4.1 で見ることができる人にだけ、5分で切れる署名付き URL を発行する。
- 申請と領収書は、振込済み、取り下げ、却下になってから10年保存し、その後に一緒に削除する。下書きは最後の編集から90日で削除する。退職した社員の下書きは退職日に削除する。差し戻しの申請は §3.2 により取り下げになり、それ以外の提出済みの申請はそのまま進める。

## 7. 振り込み

### 7.1 振込ファイル

- 締め時刻までに振込待ちになった申請を、その回の振り込みに含める。締め時刻より後に振込待ちになった申請は、次の回に含める。
- 締め時刻の翌営業日の 9:00 に、その回の申請をまとめた振込ファイルを作り、会計システムに渡す。振込先の口座は本システムでは持たず、会計システムが社員番号から引く。
- 振込ファイルには作成番号を付け、含めた申請に記録する。作成番号を記録した申請は、その結果を受け取るまで、ほかの振込ファイルに含めない。
- 会計システムに渡せなかったときは、30分ごとに3回まで渡し直す。会計システムは、同じ作成番号のファイルを二度は取り込まない。3回とも失敗したら、経理担当にメールで知らせる。経理担当は原因を取り除いてから、画面で同じ作成番号のファイルを渡し直す。実は届いていた場合でも、同じ作成番号なので二重には振り込まれない。

### 7.2 振込結果

- 会計システムは、振込日の翌営業日に、申請ごとの結果（成功、または失敗とその理由）を作成番号を付けたファイルで返す。ファイルは、振込ファイルを渡すのと同じ会計システムとの専用の接続で受け取る。本システムはそれを受けて、§3.2 のとおり振込済みか振込保留にする。申請に記録した作成番号と一致しない結果と、すでに結果を受け取った申請への結果は取り込まず、経理担当に知らせる。
- 振込日の2営業日後になっても結果が届かない申請があれば（ファイルが届かないときも、ファイルに一部の申請しか無いときも）、経理担当にメールで知らせる。申請は振込待ちのままとし、§7.1 により次の振込ファイルには含めない。経理担当は会計システムに結果を出し直させ、届いた結果で §3.2 のとおりに進める。それでも結果が得られないときは、経理担当が会計システムで振り込まれたかどうかを確かめ、申請ごとに結果を画面で入力する。入力した結果は、届いた結果と同じに扱う。
- 振込保留になった申請は、経理担当が会計システムで口座を確かめ、振り込みに戻すか却下する。振り込みに戻した申請は作成番号の記録を消し、次の回に含める。

## 8. 同時の操作

- 申請はバージョン番号を持ち、申請を変えるもの（人の操作、§3.2 のシステムによる取り下げ、§4.2 の承認者の付け替え、§7 の作成番号の記録と振込結果の取り込み）はすべてバージョン番号を上げる。システムによる変更は、その時点の申請を読み直し、変える直前にバージョン番号を確かめてから行う。人の操作は、画面が申請を読んだときのバージョン番号を送り、今のものと違えば 409 を返して何も変えない。画面は申請を読み直して、そのことを知らせる。
- これにより、上長と代理承認者が同時に承認したとき、申請者の取り下げと承認が同時に届いたとき、差し戻しと申請者の編集が同時に届いたとき、承認と 6:00 の付け替えが重なったときは、先に届いた一方だけが通る。
- システムによる取り下げと付け替えが人の操作に負けたときは、翌日にもう一度確かめる。
- 振込待ちの申請を変えるのは振込結果だけである（§3.2）。同じ申請に、経理担当の入力とファイルの結果の両方が来たときは、先の一方だけを取り込む（§7.2）。

## 9. 通知と履歴

- 状態が変わるたびに、次に操作する人と申請者に、メールと画面のお知らせで知らせる。メールの送信に失敗しても状態の変更は取り消さない。画面のお知らせには必ず残る。
- 申請を変えたもの（§8）はすべて、誰が、いつ、何をしたか（差し戻しと却下では理由も）を履歴に残す。履歴は §4.1 で申請を見ることができる人が見られ、申請と同じ期間保存する。
- 組織情報の取り込みに失敗したときは、前日の組織情報のまま動き、システム管理者にメールで知らせる。

## 10. 非機能要件

- 社員は約300人。締め時刻のある日とその前日に提出が集中し、1日に最大600件の申請を見込む。
- 画面の操作は、その集中する日でも、95% が2秒以内に応答する。
- 24時間利用できる。ただし毎月第1日曜の 2:00〜5:00 は保守のため止める（締め時刻の日には重ならない）。
- 本システムが持つ個人情報は、氏名、社員番号、所属（いずれも人事システムから取り込む）と、領収書の画像に写っているものに限る。
