# aidoc-less-is-more

ドキュメントを、`Less is More` に従って再構成する。

**伝えたいものを減らすのではなく、伝えたいものと競うもの、重なるもの、飾るだけのものを減らす。**

文書内の競合・重複・装飾を減らし、残した要素をより強く機能させる。

- **競合**は、何が主役かを曖昧にする
- **重複**は、情報の正本を曖昧にする
- **装飾**は、内容へ到達するまでの負担を増やす

目的は、文章を短くすることではない。

**減らした結果、残したものが以前より明確に働くこと**を成功とする。

## 3つの問い

以降の工程では、次の3つの問いを使う。

### Q1: 競合

> この要素は、他の要素と読み手の注意・目的・行動を競っていないか。

競合の例：

- 結論が複数ある
- 別の目的を持つ内容が途中に入る
- 補足が結論と同じ強さで書かれている
- 複数の行動が優先順位なしで並ぶ
- 見出し、太字、警告が多く、強調の差が消えている

競合は、削除だけで解消しない。

- 主役と補足に分ける
- 強調を下げる
- 順序を変える
- 注記や参照へ移す
- セクションまたは文書を分ける

### Q2: 重複

> この要素は、対象・条件・時点まで含めて、他の要素と同じ命題または役割を持っていないか。

重複の例：

- 結論を言い換えて繰り返す
- 同じ値を本文と表の両方に書く
- 同じ注意事項を複数箇所に書く
- 概要と本文が同じ役割を持つ
- 理由が結論の否定形でしかない

重複は、次のいずれかで解消する。

- 一方を正本にする
- 固有情報を一つへ統合する
- 一方を参照へ変える
- 完全に同じなら一方を削除する

### Q3: 装飾

> この要素を外しても、意味・条件・確度・行動は変わらないか。

変わらなければ装飾である。

装飾の例：

- 「重要なのは〜である」
- 避け方を示さない警告
- 基準を示さない注意書き
- 次に書く内容の予告
- 結論の言い換えでしかない理由
- 内容を増やさない強調語
- 過剰な太字
- 構造ですでに分かる関係の説明
- 接続詞による構造の実況

条件、例外、確度を表す語は、短くするためだけに削除しない。

## 用語

### 核

削除すると、読み手が宣言された行動を正しく完了できなくなる意味単位。

「正しく」には、次を含む。

- 正しい対象
- 正しい条件
- 正しい順序
- 正しい値
- 禁止事項の遵守
- 必要な分岐と復旧

### 衛星

削除しても、宣言された行動自体は完了できる意味単位。

衛星は「不要」と同義ではない。

核の理解、検証、適用を助ける場合は、核へ従属させて残す。どの核も支えない場合は、移動または削除する。

## 基本原則

1. 全文を読んでから編集する
2. 重複を処理してから必要性を判定する
3. 削除前にQAセットを作る
4. 衛星を自動的に削除しない
5. 情報の取捨選択より先に表現を磨かない
6. 削減量を成果にしない
7. 元文書の意味・条件・確度を変えない
8. 編集記録と読み手向け本文を分ける

# ワークフロー

## ステップ1: 宣言を書き出す

**まず全文を読む。**

部分だけ見て書き換え始めると、離れた箇所の重複、後ろに埋もれた結論、文書全体の競合を見落とす。

次の4項目を書き出す。

**以降の移動・統合・削除・強調は、すべてこの宣言と照合して決める。**

| 項目 | 書く内容 | 書けないとき |
|---|---|---|
| 読み手 | 誰が読むか。前提知識。読む時点でアクセスできるコード、設定、別文書 | 再構成結果が変わる場合はユーザーへ確認する |
| 目的 | 何を理解、判断、実行させるか | 依頼内容と本文から推定し、推定であることを記録する |
| 行動 | 読み終えた読み手が取る手順、選択、決定、入力 | 観察可能な状態まで具体化する |
| 結論 | もっとも大切な一文 | 複数ある場合は、優先順位を決めるか文書を分ける |

「理解する」「把握する」だけでは行動としない。

次のように、確認可能な状態まで具体化する。

```text
設定を理解する
→ 環境に応じた設定値を選べる

原因を把握する
→ 症状から確認対象を切り分けられる

仕組みを理解する
→ AとBの違いを説明できる
```

宣言は検証記録に残す。

読み手向け本文には、文書そのものに必要な場合だけ含める。

## ステップ2: 意味単位に分解する

文書を「1つのことを言っている塊」に分ける。段落単位とは限らない。

| # | 塊（冒頭20字） | 情報型 | 一言（20字以内・体言止め） | 対象・条件 |
|---|---|---|---|---|

情報型は次の6つから1つ選ぶ。自作しない。

| 情報型 | 内容 |
|---|---|
| 手順 | どうやるか。順序のある操作 |
| プロセス | 何が起きるか。時間順の出来事 |
| 原則 | 守るべき規則、方針、禁止 |
| 概念 | それが何か。定義 |
| 構造 | 何で構成されるか。部品と配置 |
| 事実 | 値、設定、状態 |

2つの情報型が当てはまる塊は、意味が混ざっている。行を分ける。

6つのどれにも当てはまらない塊は、書き手の言いたいことが確定していない可能性がある。

再構成結果に影響する場合はユーザーへ確認する。それ以外は、削除候補として記録する。

### 重複候補を見つける

次の3項目が同じ行を、重複候補とする。

- 情報型
- 一言
- 対象・条件

元の塊を照合し、次がすべて同じなら重複とする。

- 主体
- 命題
- 対象
- 条件
- 時点
- 例外

言い回しが違うだけでは、別の情報とみなさない。

重複は、次の工程へ進む前に処理する。

- 完全に同じなら一方を残す
- それぞれに固有情報があるなら一つへ統合する
- 正本が別にあるなら参照へ変える

重複を残したまま削除テストをすると、同じ内容を持つ2つの塊が互いを代替し、両方が不要だと誤判定される。

### 中間出力1

次を出力する。

1. 宣言4項目
2. 意味単位の表
3. 統合した重複の一覧

## ステップ3: 核と衛星に分け、競合を特定する

各塊について、削除テストを行う。

1. その塊を一時的に外す
2. 残りだけを読む
3. 宣言した行動を、正しい対象・条件・順序で完了できるか確認する
4. 完了できない、迷う、誤る場合は核とする
5. 正しく完了できる場合は衛星とする

重要度に中間段階を作らない。

```text
削除すると行動が成立しない → 核
削除しても行動が成立する   → 衛星
```

見た目を判定材料にしない。

- 見出し
- 太字
- コードブロック
- 分量
- 冒頭にあるかどうか

これらは、核である証拠ではない。

一方、制約、前提条件、禁止事項は、控えめに書かれていても核になり得る。

### 競合を記録する

核と衛星の判定とあわせて、次の競合を記録する。

- 衛星が核と同じ強さで見える
- 別の目的または行動を要求している
- 本筋の途中に入り、注意を切り替えさせる
- 複数の結論が主役として並んでいる
- 強調が多く、差が消えている

ステップ2の表へ次を追加する。

| 核／衛星 | 競合相手 | 競合の種類 | 判定理由 |
|---|---|---|---|

競合の種類は、次から選ぶ。

- 注意の競合
- 目的の競合
- 行動の競合
- 強調の競合

## ステップ4: 核だけを取り出して読む

核と判定した塊だけを、元の順序で並べて読む。

**ここで読むのをやめた読み手が、宣言した行動を誤らずに実行できるか。**

| 症状 | 意味 | 直し方 |
|---|---|---|
| 行動を最後まで実行できない | 核が足りない | 衛星から必要な塊を1つだけ戻し、再度確認する |
| ほぼすべてが核 | 「無いと不便」を核にしている可能性 | 「無いと行動が止まるか」で再判定する。本当に必要なら維持する |
| 必要な核が提示されるのが遅い | 順序の問題 | 手順や依存関係を壊さず、必要になる位置まで前へ移す |
| 核同士が同じ内容を持つ | 重複が残っている | 1つへ統合し、元の塊は残さない |
| 核が別の目的を持つ | 目的の競合 | セクションまたは文書を分ける |

個別の削除テストでは、AとBのどちらか一方があれば成立する場合に、AとBの両方が衛星になることがある。

核の集合だけで行動が成立しない場合は、必要最小限の衛星を1つずつ核へ戻す。

量に上限を置かない。

行数や画面数ではなく、行動が正しく成立する量を採用する。

### 冒頭へ要約を追加しない

冒頭へ新しい要約を書き足し、同じ内容を本文にも残さない。

ただし、複数の核を1つの文へ統合する場合は、新しい文を書いてよい。その場合、統合元の文は残さない。

禁止するのは、本文に加えて同じ役割の要約を追加することである。

### 中間出力2

次を出力する。

1. 核／衛星と競合を追加した意味単位の表
2. 核だけを並べた文書

## ステップ5: QAセットを作る

**実際に削除・移動する前に作る。**

削除してからQAを作ると、失われた情報について質問できず、テストが素通りする。

宣言した行動と、行動結果を変える情報を起点に質問を作る。

| 起点 | 質問の形 |
|---|---|
| 行動の各手順 | 次に何をするか。何を指定するか |
| 原則・制約 | 何をしてはいけないか。どの条件で変わるか |
| 必須の事実 | 値、対象、状態、期限は何か |
| 手順の分岐 | どの条件で処理が変わるか |
| 復旧 | 失敗したときにどう戻すか |
| 結論 | 最終的に何を判断するか |
| 外部参照 | 正しい情報をどこから取得するか |

各質問に、元文書から取った期待する答えを添える。

| QA ID | 対応する塊 | 質問 | 期待する答え |
|---|---|---|---|

元文書から答えを一意に取れない場合は、推測せず「元文書が曖昧」と記録する。

外部のコード、設定、別文書を正本として参照させる場合は、値そのものではなく、正本へ到達する方法を期待する答えにしてよい。

質問数には固定の下限を置かない。

次がすべてQAで覆われていることを確認する。

- 宣言した行動の各手順
- 行動を変える条件
- 禁止事項
- 必須の分岐
- 復旧手順
- 結果を変える値と事実
- 文書の結論

## ステップ6: 再構成する

競合・重複・装飾を、それぞれ異なる方法で処理する。

### 競合を解消する

#### 核を配置する

核は、独立して認識できる形にする。

すべてを冒頭へ移すのではなく、読み手が必要とする時点までに提示する。

手順、依存関係、時間順を壊さない。

#### 衛星の行き先を決める

各衛星について、次を問う。

> この衛星は、どの核を、どのように強めるか。

| 衛星の働き | 処理 |
|---|---|
| 核と同じ内容 | 核へ統合する |
| 核の理解を速める | 対応する核の直下へ置く |
| 核の条件や例外を示す | 対応する核の直前または直後へ置く |
| 核の妥当性を検証可能にする | 根拠または参照として後ろへ移す |
| 特定の読者だけが必要 | 注記または別セクションへ移す |
| 別の目的や行動を支える | 文書またはセクションを分ける |
| どの核も強めない | 削除する |

衛星を、核と同じ強さの独立した主張として残さない。

### 重複を解消する

- 同じ値や事実の正本を1つにする
- 固有情報を失わない形で統合する
- 同じ内容を本文と表へ二重に書かない
- 概要と本文に同じ役割を持たせない
- 同じ注意事項を複数箇所へ複製しない
- 参照で足りる箇所は、正本への参照に変える

同じ事実が複数回登場しても、役割が異なる場合は重複とは限らない。

ただし、それぞれの役割を説明できなければ一方を落とす。

### 装飾を外す

次の要素を確認する。

#### 避け方を示さない警告

```text
ここを飛ばすと、以降がすべてぶれる
慎重に判断する必要がある
注意して進めること
```

読み手が何を避けるべきか分からない場合は削除する。必要なら具体的な条件または禁止事項へ置き換える。

#### 結論の言い換えでしかない理由

```text
太字を増やさない。
増やすと強調の差がなくなるためである。
```

理由が結論の否定形であり、新しい判断材料を加えない場合は統合する。

#### 説明的な前置き

```text
〜については
〜における
〜に関して
〜という観点で
〜の観点から
```

削除して対象範囲や意味が変わらない場合は外す。

#### 内容を増やさない強調

```text
重要なのは〜である
非常に重要である
極めて大切である
```

重要度は、順序、独立した文、見出し、配置で示す。

#### 接続の実況

```text
なお
また
そして
ただし
```

接続詞を繰り返す代わりに、段落、見出し、リスト、注記へ移す。

### 関係を構造へ移す

文章で説明している関係を、構造から理解できる形へ変える。

| 文章で書いているもの | 移す先 |
|---|---|
| 「まず〜し、次に〜し、最後に〜する」 | 番号付きリスト |
| 「〜や〜、および〜」と項目を連ねる | 箇条書き |
| 「Aの場合はX、Bの場合はY」 | 表 |
| 「〜だが、一方で〜」 | 2列の表 |
| 接続詞で段落関係を説明する | 見出しまたは段落分け |
| 同じ注記を各手順へ書く | 共通の注記または原則 |

構造化は装飾を増やすために行わない。

表やリストへ移した結果、すべての要素が同じ強さで見える場合は、核と衛星の差を再確認する。

### 削除・移動候補を処理する

次に当たる要素は、削除または移動の候補とする。

| 候補 | 処理条件 |
|---|---|
| コード、設定、別文書の転記 | 読み手にアクセス権があり、参照先が安定している場合は参照へ移す |
| 「任意」「参考」「ちなみに」とされた情報 | 核を支えず、QA対象でもない場合は削除する |
| 判定基準の後に並ぶ例 | 境界、誤解、例外を示さない例は削除する |
| 同じ値や事実の2箇所目 | 正本を1つ決め、他方を削除または参照へ変える |
| 1文で足りる1段落 | 情報を削らず、1文へ統合する |
| 宣言のスコープ外 | 別文書へ移すか、参照先だけ残す |
| 実行時に取得できる前提、引数、環境 | 取得先が明確で、確認が行動を妨げない場合は移す |

削除、統合、移動を区別する。

- **削除**：固有の役割がない
- **統合**：情報は必要だが、独立した要素としては不要
- **移動**：主線には不要だが、参照価値がある

処理した要素はすべて記録する。

### 中間出力3

次を出力する。

1. 再構成後の全文
2. 処理した要素の一覧

| 要素 | 分類 | 処理 | 理由 |
|---|---|---|---|
| 対象となる要素 | 競合／重複／装飾 | 統合／降格／移動／構造化／削除 | 適用した判定 |

## ステップ7: 表現を整える

情報の取捨選択と構造が確定した後で、残した文章だけを整える。

textlintが使える環境では、`textlint-rule-preset-ja-technical-writing` を実行する。

使えない場合は、次を確認する。

| 検出対象 | 閾値 | 直し方 |
|---|---:|---|
| 1文の長さ | 100字超 | 意味単位を保って分割する |
| 1文の読点 | 3つ超 | 分割するか、並列をリストへ移す |
| 連続する漢字 | 6字超 | 語を分ける。かなを混ぜる |
| 1文の否定辞 | 2つ以上 | 向きと確度を保って分割する |
| 二重否定 | 1つ以上 | 意味を確認して肯定表現へ直す |
| 「の」の連続 | 3つ以上 | 動詞へ戻す |
| 修飾語と被修飾語の距離 | 40字超 | 修飾を直前へ移すか、別文にする |
| 同じ接続詞の反復 | 2回以上 | 段落、リスト、見出しへ移す |
| ですます／である | 混在 | 文書内で統一する |

閾値超過は、必ず直すべき誤りではない。

正式名称、コード、引用、意味上必要な表現は、理由を記録して残してよい。

### 語を照合する

次の語は、自動的に削除せず、意味を確認する。

| 対象 | 確認すること |
|---|---|
| 基本的に、一般的に、原則として | 適用範囲や例外を表していないか |
| 極めて、非常に、かなり | 程度を示す根拠があるか |
| 重要なのは〜である | 構造だけで重要度を示せないか |
| 〜という観点において | 削除して意味や対象範囲が変わらないか |
| 〜を行う、〜を実施する | 直接的な動詞へ置き換えられないか |

例外があるために「原則として」と書いている場合は、単に削除しない。可能なら例外を具体的に書く。

### 否定の向きを確認する

否定を畳むときは、意味と確度を変えない。

```text
負荷の増大を招かないとは言えない
→ 負荷が増えることがある
```

これは「負荷が増える」と同じではない。

意味、条件、確度が変わる場合は、短くするための言い換えを行わない。

## ステップ8: 検証する

次の4つをすべて実行する。

1つでも失敗した場合は、対応する工程へ戻って修正する。

### 1. QAテスト

再構成後の文書と、そこから到達できる参照先だけを使って、ステップ5の質問へ答える。

元文書は参照しない。

期待する答えと意味が一致しない場合は、対応する情報を戻すか、参照方法を修正する。

値、条件、禁止事項、順序は厳密に確認する。

説明文は、表現ではなく意味の一致で判定する。

全問通過後、処理した要素の一覧を確認する。

宣言と関係があるのにQAで覆われていない要素があれば、QAセットの漏れとして質問を追加し、再実行する。

QAは削除を検証する主要な手段であるが、唯一の手段とはしない。

### 2. 核の再読

核だけを順に読む。

次を確認する。

- 宣言した行動を正しく完了できる
- 必要な核が提示されるのが遅くない
- 手順と依存関係が崩れていない
- 衛星が核と同じ強さで見えていない
- 別の目的が主線へ混ざっていない

### 3. 重複の再確認

再構成によって、新しい重複が生まれていないか確認する。

- 見出しと冒頭文が同じ役割を持っていないか
- 表の直前に、表と同じ内容を書いていないか
- 結論を複数箇所で言い換えていないか
- 注記と本文に同じ制約を書いていないか

### 4. 最終機械検査

再構成後の全文を、ステップ7の基準で検査する。

検出された項目は、次のどちらかにする。

- 意味を保って修正する
- 意味、確度、正式名称を守るため、理由を記録して残す

未確認の検出項目を0件にする。

## Less is More確認

最後に、次を確認する。

- 主線で同時に扱う要素は減ったか
- 主役と競う要素は解消されたか
- 同じ命題や役割の重複はなくなったか
- 内容を増やさない装飾はなくなったか
- 核と衛星の差が見て分かるか
- 少ない説明で、関係が以前より明確になったか
- 残した核は、再構成前より見つけやすくなったか
- 読み手は宣言した行動を正しく実行できるか

最終判定は、次の一問で行う。

> 減らした結果、残した核は以前より強く機能しているか。

## ステップ9: 報告する

成果物を、読み手向け本文と検証記録に分ける。

### 1. 再構成後の文書

読み手が使用する完成文書を出す。

編集工程や判定理由は本文へ混ぜない。

### 2. 処理した要素

| 要素 | 分類 | 処理 | 理由 |
|---|---|---|---|
| 対象となる要素 | 競合／重複／装飾 | 統合／降格／移動／構造化／削除 | 適用した判定 |

0件の場合は「0件」と書く。

### 3. QA結果

- QA総数
- 通過数
- 修正して再実行した質問
- 元文書が曖昧だった質問
- 外部参照へ置き換えた質問

### 4. 宣言

- 読み手
- 目的
- 行動
- 結論

### 5. 機械検査の例外

修正せず残した項目がある場合は、対象と理由を書く。

文字数の増減は、必要な場合だけ最後の1行に書く。成果として扱わない。
