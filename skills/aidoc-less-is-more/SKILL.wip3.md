# aidoc-less-is-more

ドキュメントを、"Less is More" に従って再構成する。

**「削る」のではなく「デザインする」。その結果として無駄が消える。** 目的に必要な情報を選び、要素ごとに核か衛星かを決めて、構造と書き方を決め直す。

基準は読み手側に置く。ISO 24495-1（プレーンランゲージ）の4原則 — 読み手が**必要なものを得る／見つけられる／理解できる／使える**。この4つのどれかに効く変更だけをする。根拠となる文献は [references/sources.md](references/sources.md)。

## 3つの問い

文書のどこを見るときも、探すものはこの3つしかない。**3つ以外を探さない。**

| | 問い | 何で判定するか |
|---|---|---|
| **Q1** | なくても意味が変わらないものはないか | 削除テスト（行動が止まるか）→ QAテスト（答えられなくなるか） |
| **Q2** | 同じことを別の言い方で書いていないか | 「一言」の一致、同じ値の2箇所目 |
| **Q3** | 構造で伝えられるものを文章で説明していないか | 構造への移送表、接続詞の連打 |

「意味が変わらない」「同じこと」「伝えられる」は、そのままでは判定できない。**3つは探索の軸であって、判定基準ではない。** 判定は右列の手段による。

## 4つの層

工程を4層に分ける。層が上がるほど判断は混じる。**層を混ぜない。**

| 層 | ステップ | 判定の性質 |
|---|---|---|
| **0 宣言** | 1 | 判断。ここに集約する |
| **1 機械判定** | 2 | 数えて閾値と比べる |
| **2 構造** | 3〜5 | 削除テスト |
| **3 検証** | 6〜8 | QAテストの合否 |

**主観は消えない。層0と層2に残る。** 残る場所を明示し、層3で事後に反証する。これが「客観的にやる」の実際の意味である。

**中間出力** — 3地点（ステップ2・5・7の末尾）で出す。

- 対象がファイル → 同階層に `<元ファイル名>.wip<n>.md` を作る。最終成果だけ元ファイルへ上書きし、wipは残す
- 対象がチャット → `### 中間出力 n` を付けて全文を出す

以降の工程は直前の中間出力に対して行う。自分が次の工程で使うための出力なので、ユーザーの返答は待たない。

## 層0: 宣言

### ステップ 1: 宣言を書き出す

**まず全文を読む。** 部分だけ見て書き換え始めると、離れた場所にある重複も、結論が後ろにあることも見えない。

次の4項目を書き出す。**以降のすべての判定は、この宣言と照合して決める。** 文書の種類からは決めない。読み取れなければユーザーに聞く。**宣言は成果物に残す。** 残せば第三者が検証できる。

| 項目 | 書く内容 | 書けないとき |
|---|---|---|
| 読み手 | 誰が読むか。前提知識。読む時点でアクセスできるもの（コード、設定、別doc） | ユーザーに聞く |
| 目的 | 何を理解／判断／実行させるか | ユーザーに聞く |
| 行動 | 読み終えた読み手が取る手順・決定。**箇条書きで列挙する** | 目的が曖昧。目的に戻る |
| 結論 | もっとも大切な一文 | |

**「行動」は後続の全工程で使う。** 削除テストとQAテストは、ここを起点にする。「理解する」「把握する」は行動ではない。読み手が実際に打つコマンド、選ぶ選択肢、書く値のレベルまで下ろす。ここが曖昧だと、ステップ4の一致率は落ちる。

## 層1: 機械判定

### ステップ 2: 閾値で直す (Q1, Q3)

数えて、超えたものを直す。**この層では「読みやすいか」を判定しない。**

textlint が使える環境なら `textlint-rule-preset-ja-technical-writing` を実行する。無ければ下表を自分で数える。

| 検出対象 | 閾値 | 直し方 |
|---|---|---|
| 1文の長さ | 100字 | 分割する |
| 1文の読点 | 3つ | 分割する |
| 連続する漢字 | 6字 | 語を分ける、かなを混ぜる |
| 1文の否定辞 | 2つ | 肯定に畳む |
| 二重否定 | 1つ | 肯定に直す |
| 「の」の連続 | 3つ | 動詞に戻す（「機能の設定の変更の手順」→「機能を設定変更する手順」） |
| 修飾語と被修飾語の距離 | 40字 | 修飾を別の文に出す |
| 同じ助詞の連続 | 1文に2回 | 言い換える |
| 同じ接続詞の連続 | 2回 | 段落を分ける |
| ですます／である | 混在 | 統一する |

**否定を畳むときは向きを確認する。** 「負荷の増大を招かないとは言えない」は「負荷が増えることがある」であって「負荷が増えない」ではない。畳んで意味が変わるなら、畳まずに文を分ける。

#### 語の照合 (Q1) — 判断しない。一致したら直す

| 対象 | 直し方 |
|---|---|
| 「基本的に」「一般的に」「原則として」「極めて」「非常に」「かなり」 | 消す |
| 「重要なのは〜である」「〜という観点において」「〜については」「〜における」「〜に関して」「〜の観点から」 | 消す |
| 「〜を行う」「〜を実施する」 | 動詞1語に戻す |

例外があるから「基本的に」と書いたのなら、消して例外のほうを書く。

**中間出力 1** — 宣言4項目、層1適用後の全文、違反件数の表（項目・適用前・適用後）

## 層2: 構造と核判定

### ステップ 3: 意味単位に分解する (Q2)

「1つのことを言っている塊」に分ける。段落単位とは限らない。

| # | 塊（冒頭20字） | 情報型 | 一言（20字以内・体言止め） |
|---|---|---|---|

**情報型は次の6つから1つ選ぶ。** 自作しない。

| 情報型 | 内容 |
|---|---|
| 手順 | どうやるか。順序のある操作 |
| プロセス | 何が起きるか。時間順の出来事 |
| 原則 | 守るべき規則・方針・禁止 |
| 概念 | それが何か。定義 |
| 構造 | 何で構成されるか。部品と配置 |
| 事実 | 値、設定、状態 |

2つ当てはまる塊は混ざっているので、行を分ける。6つのどれにも当てはまらない塊は、書き手の言いたいことが未確定である。ユーザーへ確認するか、落とす候補に回す。

**「一言」の同じ行が2つあれば重複 (Q2)。** どちらを残すか決めてから次へ進む。20字の体言止めに揃えれば、言い回しの差が消え、同一性だけが残る。元の文のままでは、同じことを言っているかどうか判定できない。

### ステップ 4: 削除テストで核と衛星に分ける (Q1)

**重要度に段階を付けない。二値で判定する。** 中間の段を作った瞬間に判定がぶれる。「削除したら行動が止まるか」は、やってみれば決まる。

各塊について、順に実行する。

1. その塊を削除する
2. 残りだけを読み、宣言の「行動」を最後まで実行できるか確かめる
3. **実行できない → 核。実行できる → 衛星**

**見た目に騙されない。**

- 制約・前提条件は控えめに紛れ込んでいても核になりやすい
- 見出し・コードブロック・太字・分量は、核である証拠にならない

### ステップ 5: 核だけを取り出して読む (Q1)

核と判定した塊だけを順に並べて読む。**ここで読むのをやめた読み手が、宣言の「行動」を誤らずに実行できるか。**

| 症状 | 意味 | 直し方 |
|---|---|---|
| 行動を最後まで実行できない | 核が足りない | 衛星から1つだけ核に上げ、もう一度読む |
| ほぼ全部が核 | 削除テストが機能していない。「無いと不便」を核にしている | 「行動が止まるか」で判定し直す |
| 核が文書の後ろにある | 順序の問題 | 前に出す |

**量に上限を置かない。** 行数や画面で決めない。3症状が消えた時点の量を、その文書の量とする。

**冒頭のために新しく文を書き起こさない。** 書き起こしているなら、それは本文の要約であり、同じことを二度言う文書になる。核は本文から取り出すものであって、書き足すものではない。

**中間出力 2** — 塊の表（情報型・核／衛星）と、核だけを並べたもの

## 層3: 削除と検証

### ステップ 6: QAセットを作る (Q1) — 削除する前に

**削除する前に作る。** 削除してから作ると、削除した情報についての質問を作れない。テストは素通りする。

宣言の「行動」を起点に、元の文書だけが答えを持つ質問を作る。

| 起点 | 質問の形 |
|---|---|
| 行動の各手順 | 次に何をするか／何を指定するか |
| 原則・制約 | 何をしてはいけないか／どの条件で変わるか |
| 事実 | その値はいくつか |
| 手順の分岐 | 失敗したときどう戻すか |

各質問に、元文書から取った答えを添える。質問数は行動の項目数以上にする。

### ステップ 7: 再構成して削る (Q1, Q2, Q3)

- **核** → 一文で独立させ、前に出す。修飾を削って言い切る
- **衛星** → 核にぶら下げる。1主張1説明にまとめ、言い換えの重複を統合する。表・リスト・注記へ移す

**段階を強調記法で表現しない。** 太字を増やすほど、文書全体の差は小さくなる。

#### 構造へ移す (Q3)

| 文章で書いているもの | 移す先 |
|---|---|
| 「まず〜し、次に〜し、最後に〜する」 | 番号付きリスト |
| 並ぶ項目を「〜や〜、および〜」で連ねる | 箇条書き |
| 「Aの場合はX、Bの場合はY、Cの場合はZ」 | 表 |
| 「〜だが、一方で〜」の対比 | 表の2列 |
| 「なお」「また」「ただし」「そして」の連打 | 段落を分ける、見出しを立てる |

主語・助詞・文脈で伝わるものは明示しない。「本機能では、ユーザーが問題を選択することができます」→「問題を選択できる」。

番号・見出し・禁止リストがすでに読み手を動かしているなら、その理由を文章で説明しない。次のステップの内容を手前で予告するのも同じ。

#### 落とす候補 (Q1)

次に当たるものを落とす。**落とした要素は全部記録する。** ステップ8で戻すことがある。

- **読み手が実行時に自分で取れるもの** — コード、設定、別ドキュメントの転記。参照先を指す。転記は元が変わると古くなるので、残すほうが有害になりうる
- **文書が自分で「重要でない」と申告しているもの** — 「（任意）」「参考」「ちなみに」
- **判定手順を示した上での例示の列挙** — 基準を示したなら事例は要らない
- **同じ値・同じ事実の2箇所目 (Q2)** — どちらを正とするか決める
- **1文で足りることに使った1段落**
- **宣言のスコープ外** — 判定方法と「別を見よ」の一行だけ残す
- **読んでから聞ける前提・引数・環境の事前列挙**

落とす理由は「不要だと判断した」ではなく、上のどの条件に当てはまったかで書く。

**中間出力 3** — 再構成後の全文と、落とした要素の一覧

### ステップ 8: 検証する (Q1)

3つとも実行する。1つでも落ちたら直して再実行する。

#### 1. QAテスト — 情報が落ちていないか

ステップ6のQAセットに、**再構成後の文書だけ**を見て答える。**元文書は参照しない。** 元の答えと一致しない質問があれば、対応する情報を戻す。

**これがステップ7の削除を反証する唯一の手段である。** 「落としても大丈夫だと判断した」ではなく「テストが通った」で正当化する。全問一致するまでステップ7に戻る。

#### 2. 層1の再測定 — 読解コストが戻っていないか

再構成で文を書き直しているので、ステップ2の表をもう一度測る。違反0にする。

#### 3. 核の再読 — 冒頭で成立しているか

ステップ5をもう一度実行する。再構成で順序が変わり、核が後ろに戻っていることがある。

#### 判断の再現性を測る

ステップ4の削除テストには判断が残る。**独立に2回実行し、核と判定された塊の集合を比べる。**

一致率（Jaccard = 両方で核と判定 ÷ どちらかで核と判定）が **0.6 未満なら、文書ではなく宣言のほうを直す。** 「行動」が具体的に書けていないと、削除テストの結果はぶれる。文書を直しても直らない。

## 報告

順序を固定する。

1. **宣言** — 読み手・目的・行動・結論
2. **層1の測定値** — 項目ごとに適用前／適用後の件数
3. **3つの問いごとの処理結果** — `| 問い | 要素 | 当てはめた条件 | 移した先 |` の表。**Q1・Q2・Q3のすべてに行があること。** 0件の問いは「0件」と書く
4. **QAテストの結果** — 質問数、一致数、戻した情報。**全問一致してから報告する**
5. **核判定の一致率** — Jaccard値。0.6未満なら、宣言のどこが曖昧だったかを書く

Q1（削除）は結果が目に見える。Q2（重複の統合）とQ3（構造への移送）は、飛ばしても文書が壊れないので飛ばされる。0件と書けば、飛ばしたのか本当に無かったのかを区別できる。**3と4を省くと、削除工程を飛ばしたことが表に出ない。** 文字数の増減は、書くなら最後の1行。成果として提示しない。
