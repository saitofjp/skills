# aidoc-less-is-more

ドキュメントを、Less is More に従って再構成する。
Less is More とは、単に情報や文字数を減らすことではない。読み手の注意を奪い合う要素を減らし、残した要素をより強く機能させることである。

このSkillでは、文書内の**競合・重複・装飾**を見つけ、重要度の差が伝わる構造へ組み直す。**削除は目的ではない。** 何を残すかを明確にした結果として、不要なものが消える。

基準は読み手側に置く。ISO 24495-1（プレーンランゲージ）の4原則 — 読み手が**必要なものを得る／見つけられる／理解できる／使える**。この4つのどれかに効く変更だけをする。根拠となる文献は [references/sources.md](references/sources.md)。

## 入力

### 対象

第1引数を対象として扱う。

| 引数 | 対象 |
|---|---|
| ファイルパス | そのファイル |
| URL | 取得した本文 |
| 「直前の出力」など会話への参照 | 会話中の該当テキスト |

**引数が無ければ、対象を聞いてから始める。** 会話に文書らしきものが1つしか無くても、推測で始めない。この Skill は削除を伴い、成果物を元ファイルへ上書きする。対象を取り違えると、消してはいけないものを消す。

**候補が複数あるときも聞く。** パスが複数に一致した、会話に文書が複数ある、指定されたファイルが見つからない — どれも「対象が決まっていない」という同じ状態である。候補を並べて選ばせる。

対象が決まったら、**何を読み、どこへ書くかを1行で告げてから読み始める。** 上書きされる側が先に分かる。

### 宣言の既知項目

第2引数以降に `読み手=` `目的=` `行動=` `結論=` のラベルが付いていれば、ステップ1の宣言のその項目として受け取る。ラベルの無い自由文は、宣言を読み取るときの材料に加える。ユーザーがその場で明示した意図なので、文書の書きぶりより優先する。

**引数で渡された項目は、文書から読み取り直さない。** 読み直すと、書いてあるほうへ引きずられる。渡されなかった項目だけをステップ1で読み取る。

```
/aidoc-less-is-more docs/setup.md
/aidoc-less-is-more docs/setup.md 読み手=新人SRE 目的=初回セットアップを自力で完走させる
/aidoc-less-is-more 直前のチャット出力
```

## 減らす3つ

文書のどこを見るときも、探すものはこの3つしかない。**3つ以外を探さない。**

| | 何が起きているか | 見つける手段 | 直す手段 |
|---|---|---|---|
| **競合** | 複数の要素が同じ重さを主張し、どれが重要か伝わらない | 核／衛星の分離（削除テスト） | 降格・移動・分割・削除 |
| **重複** | 同じことが別の言い方で2箇所にある | 意味単位の「一言」照合 | 統合・参照化 |
| **装飾** | 内容を足していない語・言い回し・冗長な文型 | 機械検査（閾値と語の照合） | 構造化（編集層）・削除（検証層） |

「重要か」「同じことか」は、そのままでは判定できない。**3つは探索の軸であって、判定基準ではない。** 判定は「見つける手段」の列による。

**競合と重複を先に、装飾を最後に解く。** 競合と重複は構造の問題で、解けば文が動く。装飾は表現の問題で、再構成のたびに増減する。先に直しても編集でまた発生するので、測るのは最後でよい。

## 3つの手段層

工程を3層に分ける。**層を混ぜない。**

| 層 | ステップ | 手段 | 判定の性質 |
|---|---|---|---|
| **分析** | 1〜3 | 宣言、意味単位、核／衛星 | 判断。ここに集約する |
| **編集** | 4〜6 | 統合、降格、移動、構造化、分割、削除 | 分析の結果に従う。判断し直さない |
| **検証** | 7〜10 | QA、核の再読、重複の再確認、機械検査 | 合否 |

**主観は消えない。分析層に残る。** 残る場所を1層に絞り、検証層で事後に反証する。編集層で新しく判断を始めると、反証されない変更が混ざる。

**中間出力** — 2地点（ステップ3・6の末尾）で出す。

- 対象がファイル → 同階層に `<元ファイル名>.wip<n>.md` を作る。最終成果だけ元ファイルへ上書きし、wipは残す
- 対象がチャット → `### 中間出力 n` を付けて全文を出す

以降の工程は直前の中間出力に対して行う。自分が次の工程で使うための出力なので、ユーザーの返答は待たない。**返答を待つのはステップ1の宣言だけである。**

## 分析

### ステップ 1: 宣言を書き出す

**まず全文を読む。** 部分だけ見て書き換え始めると、離れた場所にある重複も、結論が後ろにあることも見えない。

次の4項目を書き出す。**以降のすべての判定は、この宣言と照合して決める。** 文書の種類からは決めない。読み取れなければユーザーに聞く。**宣言は成果物に残す。** 残せば第三者が検証できる。

| 項目 | 書く内容 | 書けないとき |
|---|---|---|
| 読み手 | 誰が読むか。前提知識。読む時点でアクセスできるもの（コード、設定、別doc） | ユーザーに聞く |
| 目的 | 何を理解／判断／実行させるか | ユーザーに聞く |
| 行動 | 読み終えた読み手が取る手順・決定。**箇条書きで列挙する** | 目的が曖昧。目的に戻る |
| 結論 | もっとも大切な一文 | 複数ある。優先順位を決めるか、文書を分ける |

#### 宣言をユーザーに確認する

**4項目を書き出したら、ステップ2に入る前に提示して、返答を待つ。** ここだけは止まる。

止まる理由は依存の向きにある。核／衛星の判定も、落とす候補も、QAセットも、すべて宣言を起点にしている。宣言がずれていれば、工程は最後まで通ったうえで、残すべきものを削る。しかもQAセットは同じ宣言から作るので、ずれたまま全問一致する。**宣言の誤りだけは、検証層で捕まらない。** だから事前に人へ出す。

提示はこの形にする。

```
### 宣言（確認をお願いします）

| 項目 | 内容 | 出どころ |
|---|---|---|
| 読み手 | … | 引数 / 文書（どこ） / 推測 |
| 目的 | … | |
| 行動 | 1. … / 2. … | |
| 結論 | … | |

このまま進めます。直すところがあれば指示してください。
```

**出どころを書く。** 引数で渡されたものか、文書に書いてあったものか、こちらが推測したものかで、ユーザーが確かめるべき行が変わる。推測の行だけ読めば済むようにする。

**読み取れなかった項目は、推測で埋めて出さない。** 空欄のまま、その項目を質問する。埋めて出すと、ユーザーは提示された案をそのまま通しやすい。とくに「行動」が推測で埋まると、削除テストの起点が架空のものになる。

**修正が返ったら、その通りに直して先へ進む。** 直した宣言を出し直す必要はない。ただし「行動」が変わったときは、変わった行動を1行で復唱してから進む。以降の判定がすべて載る項目なので、ここだけは取り違えたまま進みたくない。

**「行動」は後続の全工程で使う。** 削除テストとQAテストは、ここを起点にする。「理解する」「把握する」は行動ではない。読み手が実際に打つコマンド、選ぶ選択肢、書く値のレベルまで下ろす。コマンドを打たない説明文書なら、「AとBを使い分けられる」「症状から確認対象を切り分けられる」のように、観察できる状態まで下ろす。

### ステップ 2: 意味単位に分解する（重複を見つける）

「1つのことを言っている塊」に分ける。段落単位とは限らない。

| # | 塊（冒頭20字） | 情報型 | 一言（20字以内・体言止め） |
|---|---|---|---|

**情報型は次の6つから1つ選ぶ。** 自作しない。

| 情報型 | 内容 |
|---|---|
| 手順 | どうやるか。順序のある操作 |
| プロセス | 何が起きるか。時間順の出来事 |
| 原則 | 守るべき規則・方針・禁止 |
| 概念 | それが何か。定義 |
| 構造 | 何で構成されるか。部品と配置 |
| 事実 | 値、設定、状態 |

2つ当てはまる塊は混ざっているので、行を分ける。6つのどれにも当てはまらない塊は、書き手の言いたいことが未確定である。ユーザーへ確認するか、落とす候補に回す。

**「一言」の同じ行が2つあれば重複。** 20字の体言止めに揃えれば、言い回しの差が消え、同一性だけが残る。元の文のままでは、同じことを言っているかどうか判定できない。**ここでは印を付けるだけでよい。** 統合はステップ4で行う。

### ステップ 3: 核と衛星に分ける（競合を見つける）

**重要度に段階を付けない。二値で判定する。** 中間の段を作った瞬間に判定がぶれる。「削除したら行動が止まるか」は、やってみれば決まる。

各塊について、順に実行する。

1. その塊を削除する
2. 残りだけを読み、宣言の「行動」を最後まで実行できるか確かめる
3. **実行できない → 核。実行できる → 衛星**

**重複と印の付いた組は、1つの塊として扱う。** 別々に削除すると互いが互いを代替し、両方が衛星になる。正本にするほうを選び、それ1つでテストする。

**見た目に騙されない。**

- 制約・前提条件は控えめに紛れ込んでいても核になりやすい
- 見出し・コードブロック・太字・分量は、核である証拠にならない

#### 核だけを取り出して読む

核と判定した塊だけを順に並べて読む。**ここで読むのをやめた読み手が、宣言の「行動」を誤らずに実行できるか。**

| 症状 | 意味 | 直し方 |
|---|---|---|
| 行動を最後まで実行できない | 核が足りない。どちらか一方あれば足りる2つは、両方が衛星になる | 衛星から1つだけ核に上げ、もう一度読む |
| ほぼ全部が核 | 削除テストが機能していない。「無いと不便」を核にしている | 「行動が止まるか」で判定し直す |
| 必要になる位置より後ろに核がある | 順序の問題。ステップ5で前に出す | ここでは印だけ付ける |
| 核が2つの目的に分かれる | 目的の競合。1つの文書に収まっていない | セクションか文書を分ける |

**量に上限を置かない。** 行数や画面で決めない。表の症状が消えた時点の量を、その文書の量とする。

**中間出力 1** — 宣言4項目、塊の表（情報型・重複の印・核／衛星）、核だけを並べたものを出す。

## 編集

### ステップ 4: 統合する・降格する・分ける（重複・競合）

**統合（重複）** — ステップ2で重複と印を付けた塊を1つにする。どちらを正とするか決めてから消す。正本が文書の外（コード・設定・別doc）にあるなら、統合ではなく参照に変える。値や事実が食い違っていたら、統合ではなく矛盾なので、ユーザーに聞く。

**降格（競合）** — 衛星を核にぶら下げる。1主張1説明にまとめ、言い換えを畳む。独立した見出しや段落として並んでいる衛星は、核の下の注記・リスト項目へ落とす。

**分割（競合）** — ステップ3で「核が2つの目的に分かれる」と印を付けたなら、1つの文書に収めない。分けたそれぞれについて、ステップ1の宣言から立て直す。

**段階を強調記法で表現しない。** 重さは配置で示す。

### ステップ 5: 移動する・構造化する（競合・装飾）

**移動（競合）** — 核を一文で独立させ、読み手が必要とする時点までに出す。修飾を削って言い切る。

**すべてを冒頭へ集めない。** 手順・依存関係・時間順を壊すと、前に出した核そのものが使えなくなる。冒頭に来るのは、順序に縛られない核だけである。

**冒頭のために新しく文を書き起こさない。** 書き起こしているなら、それは本文の要約であり、同じことを二度言う文書になる。核は本文から取り出すものであって、書き足すものではない。

**例外は統合。** 複数の核を1文にまとめるときは、新しく書いてよい。ただし元の文を残さない。禁じているのは、本文をそのままにして同じ役割の要約を足すことである。

**構造化（装飾）** — 構造で伝わるものを文章で説明しない。

| 文章で書いているもの | 移す先 |
|---|---|
| 「まず〜し、次に〜し、最後に〜する」 | 番号付きリスト |
| 並ぶ項目を「〜や〜、および〜」で連ねる | 箇条書き |
| 「Aの場合はX、Bの場合はY、Cの場合はZ」 | 表 |
| 「〜だが、一方で〜」の対比 | 表の2列 |
| 「なお」「また」「ただし」「そして」の連打 | 段落を分ける、見出しを立てる |

### ステップ 6: QAセットを作ってから削除する（競合）

#### まずQAセットを作る

**削除する前に作る。** 削除してから作ると、削除した情報についての質問を作れない。テストは素通りする。

宣言の「行動」を起点に、元の文書だけが答えを持つ質問を作る。

| 起点 | 質問の形 |
|---|---|
| 行動の各手順 | 次に何をするか／何を指定するか |
| 原則・制約 | 何をしてはいけないか／どの条件で変わるか |
| 事実 | その値はいくつか |
| 手順の分岐 | 失敗したときどう戻すか |
| 結論 | 最終的に何を判断するか |
| 外部参照 | 正しい値をどこから取るか |

各質問に、元文書から取った答えを添える。答えが元文書から一意に取れなければ、推測せず「元文書が曖昧」と記録する。

**参照に置き換える情報は、期待する答えを到達方法にする。** 値を落として参照先を指すとき（次の落とす候補の1つめ）、期待する答えを元の値のままにしてはいけない。ステップ7が必ず落ち、落としたものを戻すことになる。

**数ではなくカバレッジで決める。** 行動の各手順・行動を変える条件・禁止事項・分岐・復旧手順・結果を変える値・結論が、すべてどれかの質問で覆われていること。

#### 落とす候補

次に当たるものを落とす。**落とした要素は全部記録する。** ステップ7で戻すことがある。

- **読み手が実行時に自分で取れるもの** — コード、設定、別ドキュメントの転記。参照先を指す。転記は元が変わると古くなるので、残すほうが有害になりうる
- **文書が自分で「重要でない」と申告しているもの** — 「（任意）」「参考」「ちなみに」
- **判定手順を示した上での例示の列挙** — 基準を示したなら事例は要らない
- **1文で足りることに使った1段落**
- **宣言のスコープ外** — 判定方法と「別を見よ」の一行だけ残す
- **読んでから聞ける前提・引数・環境の事前列挙**

落とす理由は「不要だと判断した」ではなく、上のどの条件に当てはまったかで書く。

**削除・統合・移動を区別して記録する。** 固有の役割がない → 削除。情報は要るが独立した要素としては要らない → 統合。主線には要らないが参照する価値がある → 移動。

**中間出力 2** — 再構成後の全文と、落とした要素の一覧を出す。

## 検証

4つとも実行する。1つでも落ちたら直して再実行する。

### ステップ 7: QAテスト — 情報が落ちていないか

ステップ6のQAセットに、**再構成後の文書と、そこから到達できる参照先だけ**を見て答える。**元文書は参照しない。** 元の答えと意味が一致しない質問は、対応する情報を戻すか、参照のたどり方を直す。

**これがステップ6の削除を反証する唯一の手段である。** 「落としても大丈夫だと判断した」ではなく「テストが通った」で正当化する。全問一致するまでステップ6に戻る。

### ステップ 8: 核の再読 — 核だけで成立しているか

ステップ3の「核だけを取り出して読む」をもう一度実行する。編集で順序が変わり、核が後ろに戻っていることがある。

### ステップ 9: 重複の再確認 — 編集で生まれていないか

**重複は装飾と同じく、文を書き直すたびに生まれる。** ステップ2で消した分とは別に、次の4つを見る。

- 見出しと直後の一文が同じ役割になっていないか
- 表の直前に、表と同じ内容を書いていないか
- 結論を2箇所で言い換えていないか
- 注記と本文に同じ制約を書いていないか

片方を消す。

### ステップ 10: 機械検査 — 装飾が残っていないか

**装飾をまとめて落とすのはここである。** 編集層で文を書き直した後の本文を測る。数えて、超えたものを直す。**この層では「読みやすいか」を判定しない。**

textlint が使える環境なら `textlint-rule-preset-ja-technical-writing` を実行する。無ければ下表を自分で数える。**未処理の検出を0件にする。** 正式名称・コード・引用・意味上必要な表現は、直すと意味が変わるので、理由を記録して残してよい。それ以外は直す。

| 検出対象 | 閾値 | 直し方 |
|---|---|---|
| 1文の長さ | 100字 | 分割する |
| 1文の読点 | 3つ | 分割する |
| 連続する漢字 | 6字 | 語を分ける、かなを混ぜる |
| 1文の否定辞 | 2つ | 肯定に畳む |
| 二重否定 | 1つ | 肯定に直す |
| 「の」の連続 | 3つ | 動詞に戻す（「機能の設定の変更の手順」→「機能を設定変更する手順」） |
| 修飾語と被修飾語の距離 | 40字 | 修飾を別の文に出す |
| 同じ助詞の連続 | 1文に2回 | 言い換える |
| 同じ接続詞の連続 | 2回 | 段落を分ける |
| ですます／である | 混在 | 統一する |

**否定を畳むときは向きを確認する。** 「負荷の増大を招かないとは言えない」は「負荷が増えることがある」であって「負荷が増えない」ではない。畳んで意味が変わるなら、畳まずに文を分ける。

#### 語の照合 — 判断しない。一致したら直す

| 対象 | 直し方 |
|---|---|
| 「基本的に」「一般的に」「原則として」「極めて」「非常に」「かなり」 | 消す |
| 「重要なのは〜である」「〜という観点において」「〜については」「〜における」「〜に関して」「〜の観点から」 | 消す |
| 「〜を行う」「〜を実施する」 | 動詞1語に戻す |
| 「〜することができる」「〜することが可能である」 | 動詞に畳む（「問題を選択することができます」→「問題を選択できる」） |
| 文脈で分かる主語・場面の明示 — 「本機能では」「本ドキュメントにおいては」 | 消す |

例外があるから「基本的に」と書いたのなら、消して例外のほうを書く。

#### 文型の照合 — 中身があるか見る

| 対象 | 直し方 |
|---|---|
| 避け方を書いていない警告 — 「慎重に判断する」「注意して進めること」 | 避ける条件か禁止事項に書き換える。書けないなら消す |
| 結論の否定形でしかない理由 — 「太字を増やさない。増やすと差が消えるからである」 | 結論に畳む |
| 構造がすでに読み手を動かしていることの説明 — 番号・見出し・禁止リストの理由づけ、次のステップの予告 | 消す |

**ここで文を分割したら、ステップ8へ戻る。** 分割は順序を動かすので、核が後ろに落ちることがある。

### 判断の再現性を測る

ステップ3の削除テストには判断が残る。**独立に2回実行し、核と判定された塊の集合を比べる。**

一致率（Jaccard = 両方で核と判定 ÷ どちらかで核と判定）が **0.6 未満なら、文書ではなく宣言のほうを直す。** 「行動」が具体的に書けていないと、削除テストの結果はぶれる。文書を直しても直らない。

## 報告

順序を固定する。

1. **宣言** — 読み手・目的・行動・結論。ステップ1で確認したものをそのまま載せる
2. **3つごとの処理結果** — `| 種類 | 要素 | 当てはめた条件 | 移した先 |` の表。**競合・重複・装飾のすべてに行があること。** 0件のものは「0件」と書く
3. **QAテストの結果** — 質問数、一致数、戻した情報、元文書が曖昧だった質問。**全問一致してから報告する**
4. **機械検査の測定値** — 項目ごとに検出件数／修正後の件数。直さずに残した項目は、対象と理由を書く
5. **核判定の一致率** — Jaccard値。0.6未満なら、宣言のどこが曖昧だったかを書く

競合の解消（削除・降格）は結果が目に見える。重複の統合と装飾の除去は、飛ばしても文書が壊れないので飛ばされる。0件と書けば、飛ばしたのか本当に無かったのかを区別できる。**2と3を省くと、削除工程を飛ばしたことが表に出ない。** 文字数の増減は、書くなら最後の1行。成果として提示しない。
