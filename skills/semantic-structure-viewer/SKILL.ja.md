# Semantic Structure Viewer

> 英語版 [SKILL.md](SKILL.md) と同じ内容の日本語版。

1枚のページに、1つのモデルとその原文を表示する。操作部は、メタ構造を描いた1本のゲージだけで、その中心にはモデルがある。ゲージは右上の小さなHUDで、表記は英語。

- **幹：原文 ━ 塊 ━ モデル（フォーカスアウト／イン）**
  - つまみを右へ動かすと抽象度が上がり、左へ戻すと言葉に戻る。
  - 途中のどこにでも止められる。塊の層では、本文が一節ずつ塊に巻かれ、右の一覧も原文の順に並ぶ。ここではまだ構造を変えない。モデルへ進むと、同じ塊の行が1枚のカードにまとまり、入れ子になって持ち場につく。続いて、つながりが結論から外へ伸びる（Formation）。
  - 塊とモデルの層では、原文とノートが左右に並び、カーソル位置が連動する（Two Pane）。
  - **▶** は、つまみのある位置から要約までを再生し、少し止まってからモデルに戻る。つまみを自動で動かすだけで、ドラッグしたときと同じアニメーションがそのまま流れる。ページを開くと自動で始まる。
- **表現：A 要約・B 線形（→ B2 スライド）・C 表（トランスフォーム）**
  - これらはモデルの表現なので、モデルからまっすぐな線で枝分かれし、モデルを通ってしか行けない。
  - 枝の先へつまみを動かすと、モデルがその表現に変わる。カードが一言の要約の語句へ飛び込み、要点がカードから出て線形のノートになり、あるいは表のセルに落ちる。線形の先はスライドで、カードが16:9のページに広がり、発表の構成案になる。
  - 同時に、構造の写しが隅へ縮んでいき、ゲームの縮小マップのように残る。左に原文、中央に表現、隅にモデルが並び、焦点を合わせると3つが同時に光る。
- **結論と注目：** 原文の結論は反転したカードで示す。注目（`role: "key"`、◆ 注目）は、結論ではないが読み手にとっていちばん大事な塊で、どの表現でも太い枠で示し、結論の陰に埋もれないようにする。
- **テーマ：light / dark / dopa light / dopa full** 既定は dark で、light にもすぐ切り替えられる。2つの dopa は、ページを [`dopagaki-generator`](../dopagaki-generator/SKILL.ja.md) のドパガキ風（ゲーム×パチンコ×アニメOP×ショート動画）に装う。黒い舞台にネオンの色で、結論は金、注目はピンク。
  - **dopa light** は、その見た目だけで、演出はない。
  - **dopa full** は、再生を演出つきのショーにする。塊が巻かれるたびに COMBO が数え、注目と結論はカットイン（ピンクと金）・フラッシュ・揺れとともに持ち場につく。要約の前には画面が暗くなり「一言でいうと……？」と問いかけ、要約はいちばん大きな火花とともに届いて、一言が語句ごとに光る。
  - dopa full は、システムが動きを減らすよう求めていても演出を出す（端末によっては、読み手が知らないうちにその設定が入っている）。演出が要らないときは dopa light を選ぶ。演出はゲージがもともと通る瞬間を飾るだけで、出す数字はすべてモデルから数えたもの。再生を画面録画すれば、そのままショート動画になる。

ページは固定のテンプレート [`assets/viewer.html`](assets/viewer.html) である。契約（[`references/semantic-structure.md`](references/semantic-structure.md)）に従うモデルなら何でも表示でき、ネットワークは要らない。原文から意味を取り出すことはせず、表示するものはすべてモデルから来る。

## 入力

- 意味構造（Semantic Structure）のファイル（`semantic-structure/1`）。原文しか無いときは、先に [`semantic-structure-builder`](../semantic-structure-builder/SKILL.ja.md) でノートを作る。ここで構造を考え出さない。
- ユーザーが望むなら、どこから始めるか。

## 手順

ツールは、このスキルのフォルダにある `scripts/build_viewer.py`（Python 3、標準ライブラリのみ）。

1. **つまみの初期位置を決める。** これは見せ方の選択であり、モデルは変えない。
   - 文章が構造になる様子を見せるなら、原文から始める（既定）。読み手はそこから動かす。
   - 読んで探るなら、モデル（`--stage model`）や表現（`--stage summary`・`linear`・`slides`・`table`）から始める。
2. **ビルドする。**
   `python3 scripts/build_viewer.py model.json -o view.html [--stage text|chunks|model|summary|linear|slides|table] [--focus ID] [--theme dark|light|auto|dopa-light|dopa-full] [--no-autoplay]`
   - builderと同じ検査器でモデルを検証し、エラーがある間は何も書き出さない。
   - 録画して見せるショーにしたいとき、またはユーザーが dopa やドパガキを求めたときは `--theme dopa-full` でビルドする。演出なしの見た目だけなら `--theme dopa-light`。どちらでビルドしたページも、いつもそのテーマで開く。
   - 保存先はユーザーの指定があればそこ、無ければモデルと同じ場所の `.semantic/<YYYYMMDD>-<slug>/view.html`。
   - コミットはユーザーに求められたときだけ行う。
3. **ブラウザで確認する**（NodeとPlaywrightが使える場合）。
   `NODE_PATH="$(npm root -g)" node scripts/check_viewer.cjs view.html`
   - エラーなく開くこと、つまみをドラッグすると段階の間を動き、離すと落ち着くことを確かめる。
   - 開くと自動で再生が始まること、各表現が表示できること、▶ で要約まで再生されてモデルに戻ること、言葉にカーソルを重ねるとモデルに焦点が移ることを確かめる。
   - カーソルを重ねると下部に詳細が出てEscで消えること、表現ではカードとミニマップが下に並ぶこと、スマホ幅ではみ出さないことを確かめる。
   - テーマが light・dark・dopa light・dopa full で切り替わること、dopa light には演出がないこと、dopa full では ▶ で要約前の煽りと要約の到着が1回ずつ出ること、テーマを変えると演出が止まること、動きを減らす設定でも dopa full の演出が出ることを確かめる。

   そのうえで自分の目でも見る。原文からモデルまでゆっくり動かして、見出しを順に読んで話になっているか、要約がきちんと着地しているかを確かめる。
4. **渡す。** パスと使い方を伝える。
   - 開くと自動で再生が始まる。▶（またはSpace）で要約まで再生してモデルに戻る。ゲージのつまみをドラッグすると部品が動く様子が見え、ラベルをクリックする（または←→）と即座に切り替わる。
   - モデルでは、枝へ動かすと線形・スライド・表に変わる（↑↓で枝を切り替え）。
   - カーソルを重ねると原文とノートがつながり、下部に詳細が出る。クリックすると反対側がそこまでスクロールする。ヘッダーの light / dark / dopa light / dopa full でテーマを切り替える。
   - dopa full では再生そのものがショーになる。動画にするなら、ページを全画面にして最初から画面録画する。

   ユーザーがローカルのファイルを開けない環境（リモート実行など）では、Artifactとして公開する。公開前に `artifact-design` スキルを読み込む。

## ビューオプション

フラグで渡すか、JSONファイルにして `--view` で渡す。ページ内のモデルとは別のブロックに入り、モデルには入らない。

```json
{ "stage": "text", "focus": "node-id", "theme": "dark", "follow": true, "autoplay": true, "lang": "ja" }
```

`theme` は `dark`（既定）・`light`・`auto`（システムの設定に合わせる）・`dopa-light`・`dopa-full`。

## しないこと

- **見た目のためにモデルを直さない。** ノートが分かりにくいなら、builderでノートを直す。見せ方だけの問題なら、ビューオプションを変える。
- **ページに原文の解析を足さない。** ページが表示するものはすべてモデルから来る。
- **原文ごとにページを書き起こさない。** テンプレートが実装である。テンプレートを改良したときは、[`references/transform-view.md`](references/transform-view.md) もテンプレートに合わせる。
