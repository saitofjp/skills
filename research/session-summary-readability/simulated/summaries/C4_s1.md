# リアルタイム対戦機能の調査まとめ

## 結論

**Vercel と Supabase だけで作れます。サービスは増やしません。**

- 試合の判定と進行は、Supabase の Postgres 関数（RPC）で行います。クライアントの申告は信用しません。
- 問題・正解・回答は、API に公開しないスキーマに置きます。
- 通知には Supabase Realtime を使います。
- この方法でも、最優先の不正対策（相手の答えが見えないこと、タイマーをいじられないこと）はサーバー側で守れます。

## 前提と要件

- **構成**: React の SPA、Supabase（DB・認証）、Vercel（ホスティング）。個人開発。
- **作りたいもの**: 2人が同じ問題を同時に解いて競う対戦。将来はマッチングとレーティングも付けたい。
- **最優先**: 不正対策。相手の答えが見えることと、タイマーの改ざんは絶対に防ぎたい。
- **避けたいこと**: 管理するサービスを3つに増やすこと。

## 最終構成

```
[SPA on Vercel]
   │ RPC 呼び出し（入口はここだけ）
   ▼
public スキーマの RPC（security definer, search_path = ''）
   │ 判定・記録、試合の行を for update でロック
   ▼
game スキーマ（API 非公開）: matches / match_players / questions / question_answers / match_answers
   │ realtime.send()
   ▼
Supabase Realtime（private channel "match:{id}"）→ 両プレイヤー
pg_cron: 止まった試合や放棄された試合の後片付け
```

## 検討して見送った選択肢

| 選択肢 | 判断 | 理由 |
|---|---|---|
| Vercel Functions の WebSocket | 見送り | 公開ベータになったばかり（2026年6月）。約5分で切断されたという検証報告がある。部屋内への一斉配信を自作する必要がある |
| WebRTC（P2P） | 見送り | 接続準備用のシグナリングと、直接つながらない回線向けの中継（TURN）が結局必要で、費用は減らない。判定がクライアント側になり、正解やスコアを守れない。通話を付けたくなったときに、通話だけ追加するのはあり |
| Cloudflare Durable Objects | 有力だったが見送り | 1試合を1オブジェクトにでき、サーバーのタイマー（Alarm）で進行できるので、実装ミスは起きにくい。ただし不正対策の強さは Supabase 案と同じで、サービスが3つになる |
| Ably / Pusher | 見送り | 今回の規模には過剰 |

DO の利点は、Supabase の機能で代わりが用意できます。

- 守るデータをクライアントから届かない場所に置く → 非公開の `game` スキーマ
- 処理を1つずつ順番に実行する → `for update` による行ロック
- 締切で自動的に進める → `now()` による締切判定と pg_cron

## 不正対策の設計

**基本方針**: クライアントには、今見えてよい情報しか渡しません。判定はすべてサーバーで行います。

### 相手の答えや正解を見せない

- ゲームのデータは `game` スキーマに置き、API に公開しません。こうすると、RLS（行単位のアクセス制御）の設定を1つ間違えても漏れません。
- 回答時の通知は「答えた」という事実だけにして、選んだ選択肢は含めません。
- `game` スキーマのテーブルは、変更をそのまま配信する機能（`supabase_realtime` publication）に追加しません。
- `realtime.messages` には broadcast の INSERT ポリシーを作りません。送信は RPC 内の `realtime.send()` だけにします。
- 問題文は出題時刻を過ぎてから `get_current_question` で返します。正誤は締切後に返します。
- 選択肢の並びはプレイヤーごとにシャッフルし、回答は選択肢の ID で受け取ります。こうすると、外部で答えを教え合っても役に立ちません。

### タイマーをいじらせない

- 出題時刻 `q_started_at` と締切 `q_deadline` は DB の `now()` で決めて保存します。クライアントのタイマーは表示専用です。
- `submit_answer` は、`now()` が出題時刻から締切までの間にあるときだけ回答を受け付けます。回答時間もサーバーで計算します。
- `(match_id, user_id, q_index)` にユニーク制約を付け、二重回答と回答の変更を防ぎます。
- `advance` は「両者が回答済み」か「締切を過ぎた」場合だけ進みます。呼び出しを何回繰り返しても、タイミングをずらしても得はしません。

### 全体で守ること

- どの RPC も、最初に「参加者か」と「今の試合の状態でその操作をしてよいか」を確認します。
- `security definer` の関数には `set search_path = ''` を付け、`anon` からは `revoke execute` しておきます。
- スコアとレートはサーバーだけが計算します。
- 実装したら Security Advisor を実行し、別ユーザーで不正な操作を試す確認用スクリプトも流します。

### 防ぎきれない不正

- **検索や他人に聞く**: 制限時間を短くし、回答の速さもスコアに入れて影響を小さくします。
- **Bot による自動回答**: 回答時間の記録から、異常に速い人や正答率が不自然な人を後から検出します。
- **回線速度の差**: 「正解数で勝敗を決め、同点のときだけ時間を比べる」ルールで影響を小さくします。

## マッチングとレーティング（後のステップ）

- **マッチング**
  - フレンド対戦（招待リンク）、ランダムマッチ、ゴースト対戦（過去の回答記録と戦う）を組み合わせます。
  - 人が少ないことへの対策として、待ち時間に応じて許容するレート差を広げます（例: ±100 から5秒ごとに +50）。20〜30秒見つからなければ、ゴースト対戦か Bot 対戦に切り替えます。
  - `find_match()` RPC で `for update skip locked` を使えば、同時に呼ばれても同じ相手を取り合いません。
- **レーティング**
  - 最初は Elo を使います（初期 1500、K=32、最初の10戦ほどは K を大きくする）。
  - レートは `advance` が試合を確定させるのと同じトランザクションで更新します。
  - 変動させるのはランダムマッチだけにします。フレンド対戦でわざと負けて稼ぐのを防ぐためです。
  - 途中で切断したら負けとして扱います。

## Supabase Realtime の無料枠

| 項目 | Free | Pro |
|---|---|---|
| 同時接続数 | 200 | 500 |
| メッセージ数 / 秒 | 100 | 500 |
| Presence メッセージ数 / 秒 | 20 | 50 |
| 月間メッセージ数 | 200万件 | 500万件 |

- 接続はブラウザ1タブで1本です。全員が対戦中なら、同時に約100試合を行えます。
- 月間メッセージ数で見ると、月に数万試合程度まで収まる見込みです。
- 上限を超えると切断されますが、supabase-js が自動で再接続します。
- Realtime には対戦中とマッチング待ちのときだけ接続すると、枠を節約できます。
- Free プランのプロジェクトは、しばらく使われないと一時停止されます。
- 個人開発の初期は Free で足ります。同時プレイが数百人規模になったら Pro を検討します。

## 作る順番

**ステップ1: 招待リンクで2人が1試合を最後まで遊べるようにする**

不正対策の仕組みは最初から入れます。後から入れると、DB を直接読み書きするクライアントのコードを書き直すことになるためです。

- `game` スキーマに5つのテーブルを作り、既存の問題を10問ほどコピーします。
- RPC を5つ作ります: `create_match`、`join_match`、`get_current_question`、`submit_answer`、`advance`。
- Realtime は private channel `match:{id}` を使い、参加者だけが受信できるように RLS を設定します。通知は `started`、`answered`、`question_closed`、`finished` の4種類です。
- 画面は4つです: 部屋を作る、参加する、対戦する、結果を見る。
- **完了の目安**
  - 別アカウントの2つのブラウザで、10問の試合を最後まで遊べる。
  - 確認用スクリプトで、次の5つの操作がすべて拒否される。
    - `game` スキーマのテーブルを直接読む
    - 他人の試合の問題を取得する
    - 締切を過ぎてから回答する
    - 同じ問題に2回回答する
    - 出題時刻より前に問題を取得する

**その後**

1. Presence で「相手が切断」を表示し、pg_cron で放棄された試合を片付ける
2. ランダムマッチ
3. Elo レート
4. ゴースト対戦
