## 正解（評価者用・クイズアプリのリアルタイム対戦 調査 T0〜T7 時点）
- 主目的: 個人開発のクイズアプリ（React SPA / Supabase / Vercel）に、2人が同じ問題を同時に解く「リアルタイム対戦」を入れる方法を決める。最優先の要件は不正対策（相手の答えが見えない・タイマーをいじれない）。サービスを増やしたくない（Vercel・Supabase の2つに留めたい）。
- 現時点の結論: Supabase だけで作る。判定はすべてサーバー側（Postgres の RPC）で行うサーバー権威型。ゲームデータは API に公開しない game スキーマに置き、クライアントの入口は RPC だけ。締切は DB の now() で判定、同時実行は行ロック（for update）、通知は Realtime の private channel と RPC 内の realtime.send()。最初の一歩は「招待リンクで2人が1試合を最後まで遊べる」ところまで（RPC 5つ・4画面）。不正対策の仕組みは最初から入れる。
- 途中で出て退けられた／置き換わった枝:
  - Vercel Functions の WebSocket（T0 で不採用）。
  - WebRTC の P2P（サーバー代は減らず、不正を防げないので不採用、T1）。
  - Cloudflare Durable Objects（利点はあるがサービスが3つになるので不採用、T5→T6。DO の利点は Supabase の非公開スキーマ・行ロック・pg_cron で代替）。
- 後回しにした脇道: ランダムマッチ・レーティング（Elo など）・ゴースト対戦（T2）。Free 枠の上限（同時接続200＝約100試合）は補足情報（T3）。
